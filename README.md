# ETL-пайплайн: витрина продаж из CSV и JSON

проект ETL-пайплайна на чистом Python: извлечение данных
из двух источников, очистка, обогащение и загрузка в базу SQLite с построением
витрины по выручке.

## Что делает пайплайн

1. **Extract** — читает данные о продажах из `data/sales.csv` и данные о клиентах
   из `data/customers.json` (имитация выгрузки из внешнего API).
2. **Transform** —
   - приводит даты к ISO-формату (`YYYY-MM-DD`);
   - чистит и приводит к числам суммы (`1 234,50 руб.` -> `1234.5`);
   - приводит названия городов и категорий к единому виду;
   - дедуплицирует записи по `order_id` (оставляет последнюю по `updated_at`);
   - обогащает продажи информацией о клиенте (имя, город, сегмент);
   - считает витрину: выручка по месяцам, категориям и сегментам клиентов.
3. **Load** — складывает сырые данные и витрину в SQLite: таблицы
   `stg_sales`, `dim_customers`, `mart_sales_monthly`.

## Структура проекта

```
etl-sales-pipeline/
├── README.md
├── requirements.txt
├── main.py                  # точка входа: запускает ETL одной командой
├── src/
│   ├── extract.py           # чтение CSV и JSON
│   ├── transform.py         # очистка, дедупликация, обогащение, витрина
│   ├── load.py              # запись в SQLite (идемпотентно, truncate-and-load)
│   └── etl_config.py        # пути, константы, настройки
├── data/
│   ├── sales.csv            # исходник №1 (сырые продажи, с грязью)
│   └── customers.json       # исходник №2 (клиенты)
└── tests/
    └── test_transform.py    # юнит-тесты на ключевые правила трансформации
```


## Что демонстрирует проект

- работу с несколькими форматами источников (CSV + JSON);
- реальную очистку данных: даты, суммы с локальным форматом, дубли, регистр;
- дедупликацию по бизнес-ключу с выбором «последней» версии записи;
- обогащение данных (join между двумя источниками);
- построение витрины (агрегация для отчётности);
- идемпотентную загрузку: повторный запуск не создаёт дублей;
- юнит-тесты на правила трансформации;
- структуру «слой стейджинга -> витрина», принятую в аналитических хранилищах.
